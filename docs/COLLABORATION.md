# 协作与交接规范

## 角色边界

### 设计负责人

- 维护 `PRD.md`：问题、目标用户、范围、页面需求与验收标准。
- 维护 `design/DESIGN_SPEC.md`：设计稿链接、布局、视觉 token、组件状态与交互说明。
- 页面开始实现前，确认“设计可开发”：关键状态、空态、加载态、错误态和响应式规则齐全。

### 前端负责人

- 维护 `engineering/IMPLEMENTATION_PLAN.md`：技术决策、任务状态、风险与验证记录。
- 对设计说明中的不确定项提出问题；未经确认，不自行臆测关键交互或文案。
- 完成实现后，提供可访问页面、提交链接和自测结果给设计负责人验收。

## 页面交接卡

每新增或修改一个页面，设计负责人在 PRD 或设计规范中补齐：

| 字段 | 内容 |
| --- | --- |
| 页面名称/路由 | 待填写 |
| 目标与核心任务 | 待填写 |
| 设计稿链接 | 待填写 |
| 复用组件 | 待填写 |
| 交互规则 | 待填写 |
| 状态覆盖 | 默认 / 加载 / 空 / 错误 / 无权限（按需） |
| 响应式规则 | 待填写 |
| 验收标准 | 待填写 |

前端负责人接收后，在实现计划登记：任务负责人、分支名、状态、预览地址和测试结果。

## Git 约定

- `main`：稳定、可验收版本；不要直接提交未验证的改动。
- 功能分支：`feat/<页面或功能>`；文档分支：`docs/<主题>`；修复分支：`fix/<问题>`。
- 提交信息示例：`feat: add landing hero section`、`docs: define checkout acceptance criteria`。
- 合并前至少由另一位协作者检查：设计改动核对需求完整性，代码改动核对页面效果与验收项。

## 完成定义（Definition of Done）

- PRD 和设计稿/设计说明已关联，页面目标与边界清楚。
- 默认态及所有必要的异常状态均已实现。
- 桌面端与移动端规则已按设计验证。
- 无阻塞级控制台错误；核心流程已手动验证。
- 设计负责人按验收标准确认，未解决问题已明确记录。
